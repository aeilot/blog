How Close Is FlashAttention to the Limit? Understanding Attention Through Data Movement

Reading Barna Saha and Christopher Ye, The I/O Complexity of Attention, or How Optimal is Flash Attention? (2024). Original paper

We often measure an algorithm’s cost in FLOPs. On a GPU, however, less arithmetic does not necessarily mean less time: arithmetic units may be waiting for data to travel from device memory to on-chip storage. FlashAttention’s central contribution is to reduce that movement. This paper asks a further question: how much room remains?

The answer depends on the memory regime. In the paper’s large-cache model, FlashAttention already achieves the optimal asymptotic I/O complexity. With a small cache, a different tiling strategy does better. Optimality here concerns the order of data movement, rather than the fastest possible implementation.

Attention as a mathematical problem

For a single attention head, let

Q,K,V∈RN×d.Q,K,V\in\mathbb R^{N\times d}. Q,K,V∈RN×d.

Here NNN is the sequence length and ddd the head dimension. The score between query iii and key jjj is

sij=∑ℓ=1dQiℓKjℓ.s_{ij}=\sum_{\ell=1}^{d}Q_{i\ell}K_{j\ell}. sij​=ℓ=1∑d​Qiℓ​Kjℓ​.

Actual models usually divide this score by d\sqrt dd​. That scaling does not change the I/O orders discussed here, so we omit it.

Softmax turns each row of scores into weights:

pij=esij∑t=1Nesit.p_{ij}=\frac{e^{s_{ij}}}{\sum_{t=1}^{N}e^{s_{it}}}. pij​=∑t=1N​esit​esij​​.

The output is a weighted average:

Oir=∑j=1NpijVjr.O_{ir}=\sum_{j=1}^{N}p_{ij}V_{jr}. Oir​=j=1∑N​pij​Vjr​.

In matrix form,

O=softmax⁡(QK⊤)V.O=\operatorname{softmax}(QK^\top)V. O=softmax(QK⊤)V.

Computing both products with classical matrix multiplication takes roughly 4N2d4N^2d4N2d FLOPs, counting multiplication and addition separately and ignoring lower-order terms. Yet the intermediate score matrix has N2N^2N2 entries, while the output has only NdNdNd. Must we store that enormous intermediate matrix?

Two memory levels: a warehouse and a workbench

The paper uses an idealized model. Slow memory is large; fast memory holds only MMM numbers. All computation happens in fast memory, and each number loaded or stored counts as one I/O operation.

On a GPU, we can think of the slow level as device memory and the fast level as on-chip storage. Real hardware has registers, shared memory, and multiple cache levels; the model abstracts one boundary within that hierarchy.

The units matter. MMM counts elements, rather than bytes. If fast memory holds CCC bytes and each element occupies www bytes, then

M=⌊Cw⌋.M=\left\lfloor\frac Cw\right\rfloor. M=⌊wC​⌋.

Moving LLL elements means transferring wLwLwL bytes. The paper seeks the smallest possible asymptotic order of LLL, rather than directly predicting seconds.

Softmax without storing the score matrix

Fix one query and define

z=∑jesj,u=∑jesjvj.z=\sum_j e^{s_j},\qquad u=\sum_j e^{s_j}v_j. z=j∑​esj​,u=j∑​esj​vj​.

Then its output is o=u/zo=u/zo=u/z. We can process keys and values block by block, adding each block’s contributions to zzz and uuu without retaining every score.

For numerical stability, implementations also maintain a maximum mmm and use

ℓ=∑jesj−m,u=∑jesj−mvj.\ell=\sum_j e^{s_j-m},\qquad u=\sum_j e^{s_j-m}v_j. ℓ=j∑​esj​−m,u=j∑​esj​−mvj​.

If the new block’s score indices form a set JJJ, update the maximum to

m′=max⁡(m,max⁡j∈Jsj).m'=\max\left(m,\max_{j\in J}s_j\right). m′=max(m,j∈Jmax​sj​).

The existing accumulators must be rescaled:

ℓ′=em−m′ℓ+∑j∈Jesj−m′,u′=em−m′u+∑j∈Jesj−m′vj.\begin{aligned} \ell'&=e^{m-m'}\ell+\sum_{j\in J}e^{s_j-m'},\\ u'&=e^{m-m'}u+\sum_{j\in J}e^{s_j-m'}v_j. \end{aligned} ℓ′u′​=em−m′ℓ+j∈J∑​esj​−m′,=em−m′u+j∈J∑​esj​−m′vj​.​

The final output remains o=u/ℓo=u/\ello=u/ℓ. These equations explain why score computation can be fused with accumulation and the score blocks discarded. They are background for understanding FlashAttention, rather than new contributions of this lower-bound paper. Exact attention means evaluating the same mathematical function; changing floating-point execution order can still change rounding.

Large caches: where FlashAttention’s I/O comes from

Let BBB be the number of queries in a fast-memory block. Each query needs ddd elements, alongside output accumulators and temporary storage. Ignoring constants,

B=Θ(M/d).B=\Theta(M/d). B=Θ(M/d).

One intuitive schedule keeps a query block and its output state in fast memory, then scans all of K,VK,VK,V. Each scan costs Θ(Nd)\Theta(Nd)Θ(Nd), and there are about N/BN/BN/B query blocks. The leading term is therefore

L=Θ(NB⋅Nd)=Θ(N2d2M).L=\Theta\left(\frac NB\cdot Nd\right) =\Theta\left(\frac{N^2d^2}{M}\right). L=Θ(BN​⋅Nd)=Θ(MN2d2​).

As a teaching example, take N=4096,d=64,M=65536N=4096,d=64,M=65536N=4096,d=64,M=65536 elements.

Nd=262144,N2d2M=1048576.Nd=262144,\qquad \frac{N^2d^2}{M}=1048576. Nd=262144,MN2d2​=1048576.

These are values of asymptotic expressions, rather than exact load and store counts. Actual block sizes must reserve room for accumulators, temporary scores, and other state. The example illustrates the scaling: in this regime, doubling fast memory can roughly halve the leading movement term.

The paper proves a matching lower bound for the classical matrix multiplication model when M≥d2M\ge d^2M≥d2. This is more than a convenient tiling strategy: alternative schedules cannot improve its asymptotic order.

Small caches: when storing an intermediate matrix helps

When M<d2M\lt d^2M<d2, tiling around whole vectors of dimension ddd is too restrictive. Instead, use square blocks with side length

b=Θ(M)b=\Theta(\sqrt M) b=Θ(M​)

so that two input blocks and an output block fit in fast memory. A local product uses Θ(b2)\Theta(b^2)Θ(b2) elements to support Θ(b3)\Theta(b^3)Θ(b3) scalar multiply-adds, giving reuse efficiency Θ(b)=Θ(M)\Theta(b)=\Theta(\sqrt M)Θ(b)=Θ(M​).

The two attention products require Θ(N2d)\Theta(N^2d)Θ(N2d) multiply-adds in total, so this strategy achieves

L=O(N2dM).L=O\left(\frac{N^2d}{\sqrt M}\right). L=O(M​N2d​).

It writes the exponentiated score matrix to slow memory, consuming Θ(N2)\Theta(N^2)Θ(N2) space. But the small-cache condition implies

N2dM>N2.\frac{N^2d}{\sqrt M}\gt N^2. M​N2d​>N2.

Writing N2N^2N2 elements therefore does not increase the asymptotic leading term. Never storing an intermediate matrix is not a universally optimal rule.

Compare the two strategies:

N2d2/MN2d/M=dM.\frac{N^2d^2/M}{N^2d/\sqrt M}=\frac d{\sqrt M}. N2d/M​N2d2/M​=M​d​.

For M<d2M\lt d^2M<d2, the ratio exceeds one and square tiling moves less data. For M>d2M\gt d^2M>d2, FlashAttention-style fused tiling does better. The crossover is precisely M=d2M=d^2M=d2.

Putting the regimes together

Theorem 3.1 gives the following leading term for classical matrix multiplication:

Θ(min⁡{N2dM,N2d2M}).\Theta\left(\min\left\{ \frac{N^2d}{\sqrt M}, \frac{N^2d^2}{M} \right\}\right). Θ(min{M​N2d​,MN2d2​}).

For ordinary attention dimensions, including compulsory input and output traffic, it is useful to understand this as

Lclassical=Θ(Nd+min⁡{N2dM,N2d2M}).L_{\mathrm{classical}} =\Theta\left(Nd+\min\left\{ \frac{N^2d}{\sqrt M}, \frac{N^2d^2}{M} \right\}\right). Lclassical​=Θ(Nd+min{M​N2d​,MN2d2​}).

The added NdNdNd emphasizes the cost of reading inputs and writing outputs. With an extremely large cache, the leading-term expression cannot be extrapolated to traffic smaller than the output itself. Here we assume the common regime d≤Nd\le Nd≤N; extreme rectangular shapes require explicit checks of block dimensions and compulsory I/O.

Proving a lower bound for a fixed computation graph

The red-blue pebble game represents dependencies as a DAG. Inputs and intermediate values are vertices, and dependencies are edges. Red pebbles represent values in fast memory, with at most MMM available; blue pebbles represent values in slow memory.

There is no need to enumerate every schedule. Divide an execution into phases of MMM I/O operations, then ask how many scores one phase can complete.

In the large-cache regime, the paper proves that a phase can complete only

O(M2/d2)O(M^2/d^2) O(M2/d2)

entries of QK⊤QK^\topQK⊤. Intuitively, each query or key vector requires ddd elements. About M/dM/dM/d queries and M/dM/dM/d keys can form only about (M/d)2(M/d)^2(M/d)2 pairs.

A rigorous proof must also handle partially computed dot products. Counting complete vectors alone is insufficient. The paper analyzes summation trees and partition boundaries to account for these partial computations.

There are N2N^2N2 scores, so at least Ω(N2d2/M2)\Omega(N^2d^2/M^2)Ω(N2d2/M2) phases are needed. Multiplying by the Θ(M)\Theta(M)Θ(M) movement budget per phase gives

L=Ω(N2d2M).L=\Omega\left(\frac{N^2d^2}{M}\right). L=Ω(MN2d2​).

What if we use a Strassen-like algorithm?

A proof for a fixed DAG does not automatically rule out another matrix multiplication algorithm: changing the algorithm changes the graph. The paper’s second part addresses this distinction.

The authors introduce a communication problem called matrix entry compression. Alice knows the input matrices and sends Bob a short message. Bob must recover BBB entries of their product. If those entries contain substantial independent information, the message cannot be arbitrarily short.

The key communication lower bound has the form

message length=Ω(min⁡{dB,B})\text{message length} =\Omega\left(\min\{d\sqrt B,B\}\right) message length=Ω(min{dB​,B})

measured in finite-field elements. An I/O phase has an information budget of only O(M)O(M)O(M) elements, so it can produce at most

B=O(max⁡{M2d2,M})B=O\left(\max\left\{\frac{M^2}{d^2},M\right\}\right) B=O(max{d2M2​,M})

product entries. This yields the lower bound in Theorem 4.8:

L=Ω(min⁡{N2d2M,N2}).L=\Omega\left(\min\left\{\frac{N^2d^2}{M},N^2\right\}\right). L=Ω(min{MN2d2​,N2}).

When M≥d2M\ge d^2M≥d2, this matches FlashAttention’s leading term. The proof uses a finite field Fq\mathbb F_qFq​ with q>Nq\gt Nq>N and constructions based on linear independence. The corresponding binary-input result loses logarithmic factors. It cannot be applied without qualification as an information-theoretic theorem for arbitrary floating-point representations.

The scope also matters: the extension allows different matrix multiplication methods while still computing entries of QK⊤QK^\topQK⊤. It is not an unrestricted lower bound for every conceivable attention algorithm that might bypass those explicit entries, use approximation, or exploit special inputs.

For small caches, the authors connect attention to the I/O complexity of rectangular matrix multiplication. Once fast matrix multiplication is allowed, the paper does not supply one tight closed-form expression covering every case.

From a movement lower bound to a performance upper bound

The following is an application of the paper to performance modeling. If at least Lmin⁡L_{\min}Lmin​ elements must cross a memory boundary, each occupies www bytes, and that boundary has a bandwidth ceiling β\betaβ, then

T≥wLmin⁡β.T\ge\frac{wL_{\min}}\beta. T≥βwLmin​​.

If the chosen algorithm class also requires at least Fmin⁡F_{\min}Fmin​ FLOPs, and the compute ceiling at the relevant precision is PPP, then

T≥max⁡{Fmin⁡P,wLmin⁡β}.T\ge\max\left\{\frac{F_{\min}}P,\frac{wL_{\min}}\beta\right\}. T≥max{PFmin​​,βwLmin​​}.

Taking the maximum allows ideal overlap between computation and transfer. This is an optimistic time lower bound, rather than a prediction of actual runtime. An asymptotic Ω\OmegaΩ expression alone also supplies no reliable numerical constant.

For a Bound Estimator on a Mac, first specify the memory boundary, effective capacity, precision, and algorithm class. Unified memory does not eliminate movement between on-chip storage and DRAM.

The paper studies full N×NN\times NN×N attention. Single-token decoding has query length one, so its cost cannot be obtained by copying an N2N^2N2 formula. It needs rectangular analysis and a separate account of where the existing KV state resides.

What remains after reading the paper?

FlashAttention lets a score complete its entire purpose in fast memory: it is generated, participates in normalization and weighted accumulation, then disappears. The lower-bound paper shows that, in the specified model’s large-cache regime, this strategy reaches the asymptotic limit of data movement.

There is still distance between optimal movement and minimum runtime. Parallelism, instruction throughput, synchronization, register occupancy, and constant factors remain open to improvement. Theory is most useful when it tells us where an improvement in asymptotic order is still possible, and where the next gains must come from implementation efficiency.
