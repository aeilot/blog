Beyond FLOPs: How COSMA Builds Parallel Matrix Multiplication from Communication Bounds

Reading Grzegorz Kwasniewski et al., Red-blue pebbling revisited: near optimal parallel matrix-matrix multiplication (2019, arXiv v3). Original paper

Suppose a matrix multiplication requires a trillion multiply-adds. Adding processors seems as though it should keep shortening the runtime. Yet each processor must receive its inputs, and partial results from different processors may need to be combined. As arithmetic gets faster, movement can become the bottleneck.

COSMA begins with a question: what reuse does finite memory permit? It then seeks a work decomposition with as little communication as possible and turns that decomposition into parallel matrix multiplication.

Its focus is classical matrix multiplication, where each output is an ordinary sum of products. The same optimality claim does not include Strassen-like algorithms.

Three indices form a three-dimensional computation space

Let

A∈Rm×k,B∈Rk×n,C=AB∈Rm×n.A\in\mathbb R^{m\times k},\quad B\in\mathbb R^{k\times n},\quad C=AB\in\mathbb R^{m\times n}. A∈Rm×k,B∈Rk×n,C=AB∈Rm×n.

Each output entry is

Cij=∑ℓ=1kAiℓBℓj.C_{ij}=\sum_{\ell=1}^{k}A_{i\ell}B_{\ell j}. Cij​=ℓ=1∑k​Aiℓ​Bℓj​.

A scalar multiply-add corresponds to a triple (i,j,ℓ)(i,j,\ell)(i,j,ℓ). The whole computation can therefore be pictured as an m×n×km\times n\times km×n×k box containing mnkmnkmnk multiply-add positions.

Suppose a processor receives an a×b×ca\times b\times ca×b×c sub-box. The three data sets it needs are exactly the projections of that box onto three coordinate planes:

Data Local shape Elements
AAA a×ca\times ca×c acacac
BBB c×bc\times bc×b bcbcbc
Partial sums of CCC a×ba\times ba×b ababab

The local work is abcabcabc, and the boundary volume of inputs and final local outputs is ac+bc+abac+bc+abac+bc+ab. A large computation volume with a small boundary means substantial reuse.

Why a square root appears in the lower bound

Let fast memory hold SSS elements. If three square tiles of side length ttt all reside there, then

3t2≤S,t=Θ(S).3t^2\le S, \qquad t=\Theta(\sqrt S). 3t2≤S,t=Θ(S​).

Loading Θ(t2)\Theta(t^2)Θ(t2) numbers supports Θ(t3)\Theta(t^3)Θ(t3) multiply-adds. Each transferred number supports Θ(t)\Theta(t)Θ(t) multiply-adds, so the reuse scales as S\sqrt SS​, rather than SSS.

The whole multiplication has mnkmnkmnk multiply-adds. The leading term of the classical I/O lower bound is therefore

L=Ω(mnkS).L=\Omega\left(\frac{mnk}{\sqrt S}\right). L=Ω(S​mnk​).

This square-tile example explains the exponent 1/21/21/2, but does not prove a bound for all schedules. A rigorous proof must handle irregular tiles, partial sums, recomputation, and reuse across phases.

COSMA starts from red-blue pebbling and graph partitions to make the reuse analysis more precise, paying particular attention to constants hidden by asymptotic notation.

A better sequential schedule: retain outputs and stream inputs

Keeping three large tiles simultaneously is not the only strategy. We can retain an a×ba\times ba×b output tile in fast memory while streaming column segments of AAA and row segments of BBB through it.

For a fixed ℓ\ellℓ, the update is an outer product:

Cblock←Cblock+Ablock,ℓBℓ,block.C_{\mathrm{block}} \leftarrow C_{\mathrm{block}} +A_{\mathrm{block},\ell}B_{\ell,\mathrm{block}}. Cblock​←Cblock​+Ablock,ℓ​Bℓ,block​.

Reading a+ba+ba+b numbers completes ababab multiply-adds, giving reuse efficiency

ρ=aba+b.\rho=\frac{ab}{a+b}. ρ=a+bab​.

For a fixed output area ab=Rab=Rab=R, the arithmetic–geometric mean inequality gives

a+b≥2ab=2R,a+b\ge2\sqrt{ab}=2\sqrt R, a+b≥2ab​=2R​,

so efficiency is greatest at a=b=Ra=b=\sqrt Ra=b=R​:

ρmax⁡=R2.\rho_{\max}=\frac{\sqrt R}{2}. ρmax​=2R​​.

Most of the memory should therefore hold an output tile as close to square as possible, supported by smaller input buffers.

Each output tile is written only after traversing the full kkk dimension. Ignoring edges, divisibility, and buffer space, tiles with side length roughly S\sqrt SS​ give leading input traffic

mnS⋅2kS=2mnkS.\frac{mn}{S}\cdot2k\sqrt S =\frac{2mnk}{\sqrt S}. Smn​⋅2kS​=S​2mnk​.

Add mnmnmn elements for the final output. This explains the coefficient 2 that the paper studies closely, and why repeatedly writing partial sums wastes communication.

In a real schedule, not all SSS positions can hold output: inputs and newly computed values also need space. The paper explicitly handles this executability constraint. Its near-optimal factor has the form

SS+1−1,\frac{\sqrt S}{\sqrt{S+1}-1}, S+1​−1S​​,

which approaches one as SSS grows. A figure such as 0.03% describes closeness to a communication guarantee within the model; it does not mean runtime is within 0.03% of hardware peak performance.

From fixed partitions to proofs that account for reuse

The classical Hong–Kung argument cuts an execution by I/O count and uses partition boundaries to limit the work in each phase. COSMA further distinguishes values already resident at phase entry, values that must be newly loaded, and results that must be saved.

Its reuse lemma uses XXX as the partition parameter, R(S)R(S)R(S) as an upper bound on the reuse set, and T(S)T(S)T(S) as a lower bound on necessary stores, obtaining

L≥(X−R(S)+T(S))(H(X)−1),L\ge\bigl(X-R(S)+T(S)\bigr)\bigl(H(X)-1\bigr), L≥(X−R(S)+T(S))(H(X)−1),

where H(X)H(X)H(X) is the minimum number of subcomputations in a valid partition.

This is more precise than simply assigning SSS transfers to every phase. Existing values can be reused, but all of fast memory cannot simultaneously be reserved for reuse while additional inputs occupy space outside that budget. Executability must be counted too.

The paper first analyzes greedy schedules that reuse data promptly, then argues that non-greedy schedules cannot beat the corresponding lower bound. Greedy has a formal definition here; it does not mean an arbitrary local heuristic.

Any concrete bound also requires checking the input/output convention and dimension regime. Traffic changes if inputs already occupy the target memory level, or the entire problem fits there. Usually we should also check the compulsory cost

L≥mk+kn+mnL\ge mk+kn+mn L≥mk+kn+mn

under the usual convention that inputs start in slow memory and outputs must be written back. The communication leading term cannot be extrapolated indefinitely without these conditions.

When should parallel multiplication split the third dimension?

Suppose there are ppp processors, each with local capacity SSS. With balanced work, each processor performs

W=mnkpW=\frac{mnk}{p} W=pmnk​

multiply-adds.

Splitting only the i,ji,ji,j dimensions gives each processor a final output tile accumulated over the complete ℓ\ellℓ dimension. Its partial sums need no cross-processor reduction. But as processor count grows, output tiles shrink and input reuse declines.

Splitting ℓ\ellℓ as well lets several processors compute different contributions to the same output tile:

C(r)=∑ℓ∈IrA∗,ℓBℓ,∗,C=∑rC(r).C^{(r)}=\sum_{\ell\in I_r}A_{*,\ell}B_{\ell,*}, \qquad C=\sum_rC^{(r)}. C(r)=ℓ∈Ir​∑​A∗,ℓ​Bℓ,∗​,C=r∑​C(r).

This preserves larger local output tiles but requires communication to reduce partial sums. The choice between two and three dimensions should follow the problem shape, processor count, and available memory.

A local optimization we can solve by hand

Consider a local work domain a×a×ba\times a\times ba×a×b. Its work is a2b=Wa^2b=Wa2b=W, and its ideal boundary communication is

Llocal=2ab+a2.L_{\mathrm{local}}=2ab+a^2. Llocal​=2ab+a2.

Substitute b=W/a2b=W/a^2b=W/a2:

Llocal(a)=2Wa+a2.L_{\mathrm{local}}(a)=\frac{2W}{a}+a^2. Llocal​(a)=a2W​+a2.

The first term falls as aaa grows because input reuse improves. The second rises because the partial-result tile grows.

Differentiate:

dLlocalda=−2Wa2+2a.\frac{dL_{\mathrm{local}}}{da} =-\frac{2W}{a^2}+2a. dadLlocal​​=−a22W​+2a.

Setting the derivative to zero gives

a3=W,a=b=W1/3.a^3=W,\qquad a=b=W^{1/3}. a3=W,a=b=W1/3.

When memory permits, the ideal local domain is a cube, with

Llocal=3W2/3.L_{\mathrm{local}}=3W^{2/3}. Llocal​=3W2/3.

But the output tile must satisfy a2≤Sa^2\le Sa2≤S. If the cube’s face does not fit, cap aaa at S\sqrt SS​ and extend the accumulation dimension. The ideal solution becomes

a=min⁡{S,W1/3},b=Wa2.a=\min\{\sqrt S,W^{1/3}\},\qquad b=\frac{W}{a^2}. a=min{S​,W1/3},b=a2W​.

Its continuous geometric cost is

Llocal={3W2/3,W2/3≤S,2W/S+S,W2/3>S.L_{\mathrm{local}}= \begin{cases} 3W^{2/3},&W^{2/3}\le S,\\ 2W/\sqrt S+S,&W^{2/3}>S. \end{cases} Llocal​={3W2/3,2W/S​+S,​W2/3≤S,W2/3>S.​

This is an ideal model for understanding the design. It ignores integer processor grids, edge tiles, input buffers, and dimension limits. A local domain cannot exceed a short matrix dimension; the actual decomposition must be clipped and redistributed.

The two branches cannot simply be compared and the smaller selected unconditionally. The cubic branch is feasible only if its face fits in memory.

Why minimum communication is not always minimum runtime

Each message incurs startup latency as well as transmission time. A common model is

Tcomm≈αr+wLβ,T_{\mathrm{comm}}\approx\alpha r+\frac{wL}{\beta}, Tcomm​≈αr+βwL​,

where rrr is the number of communication rounds, α\alphaα the latency per round, www the element width in bytes, and β\betaβ the effective bandwidth.

Combining many small messages into a larger one reduces rrr, but requires more buffer space. Receiving hhh input groups at once changes the local constraint to

a2+2ah≤S.a^2+2ah\le S. a2+2ah≤S.

Communication volume, message count, and memory capacity must therefore be balanced together. COSMA also overlaps communication with computation, preallocates buffers, optimizes broadcasts and reductions, and uses local BLAS.

Processor count affects grid shape too. The paper gives an example in which 65 processors are difficult to arrange into a suitable regular grid, while 64 can form a 4×4×44\times4\times44×4×4 grid and may communicate less. Using every available processor and achieving the shortest runtime are different objectives.

What the experiments establish

The paper compares COSMA with ScaLAPACK, CARMA, and CTF on the CPU partition of Piz Daint, covering square and elongated matrices at several scales. Its abstract reports speedups up to 12.8 times, averaging 2.2 times over those baselines, and performance reaching 88% of the platform’s peak compute rate.

These are results for the 2019 paper’s particular platform, baselines, and experiments. They are not guarantees for every modern GPU or matrix shape. The valuable lesson is the complete chain from lower bound, through decomposition, to implementation.

What this suggests for inference performance research

To estimate a performance limit without relying on an existing kernel, COSMA suggests a method: describe the permitted scalar computation and reuse, derive minimum communication under memory constraints, then connect it to device bandwidth.

The argument still assumes classical matrix multiplication. Independence from an existing implementation does not eliminate algorithmic assumptions.

If several Transformer matrix multiplications are fused, one operator’s output may remain in fast memory for the next. We cannot mechanically add compulsory writeback costs for isolated operators. The lower bound must describe the permitted fusion scope and residency state.

COSMA’s central idea becomes a concrete question: how should this memory be organized so that every transferred number participates in as much useful computation as possible? Answering that before selecting a fixed processor grid gives the decomposition a reason to exist.
